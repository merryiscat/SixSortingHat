# 화면 기획 규약

SixSortingHat 챗봇의 흑백 와이어프레임 작업 규약. `screen-plan` 스킬은 시각 규칙·구조를
책임지고, **도메인 어휘는 이 문서가 권위**다. 화면을 새로 그리거나 고치기 전에 반드시 읽는다.

> **이 문서는 2026-08-03에 전면 재작성되었다.** 옛 규약(커밋 `561ef80`)은 모자 탈락제와
> "의견 하나"를 단위로 삼았으나 도메인이 아이디어 탈락제 + 파랑 지휘형으로 바뀌었다.
> 옛 문서를 참고하지 마라 — 단위·점수 체계·화면 위계가 전부 다르다.

## 전제

- 반응형 웹, **모바일 우선** (375 default → 768 → 1024)
- **개입형** — 라운드 사이에 사용자가 방향을 튼다. 이것이 이 서비스의 핵심 상호작용이다
- 화면 경로는 `docs/screens/` 로 고정
- 공용 스타일은 `wireframe.css`. 새 컴포넌트가 필요하면 여기에 추가한다

## 영역 prefix

| Prefix | 영역 | 화면 |
|---|---|---|
| I | 입력 / 시작 | I1 주제 입력, I2 파랑의 확인 질문 |
| D | 토론 (Discussion) | D1 라운드 진행, D2 라운드 종료 확인 |
| R | 결과 (Result) | R1 최종 보고서 |
| H | 기록 (History) | H1 토론 기록 |
| S | 설정 (Settings) | S1 설정 |

ID·이름·목적은 1:1 고유. 다른 화면에서 참조할 때는 ID로만 호출한다.
새 영역이 필요하면 prefix를 추가하고 이 표를 갱신한다.

## 모자 명칭 — 고정

**하양 / 빨강 / 검정 / 노랑 / 초록 / 파랑** 6개만 사용한다. 프로젝트 루트 `README.md`가
원천이며, 임의 별칭("비평가", "낙관이" 등)을 만들지 않는다. 화면에는 모자명 + 역할 라벨을
함께 노출한다.

| 모자 | 역할 라벨 | 담당 축 (채점) |
|---|---|---|
| 하양 | 사실·정보 | 근거 0.25 |
| 빨강 | 감정·직관 | 호응 0.10 |
| 검정 | 위험·비판 | 위험 내성 0.20 |
| 노랑 | 이점·기회 | 실행가능성 0.20 |
| 초록 | 창의·대안 | 독창성 0.10 |
| 파랑 | 진행·종합 | 주제 적합성 0.15 |

**파랑은 다른 5개와 동급이 아니다.** 라운드를 설계하고 지휘한다. 5개와 같은 줄·같은 카드
스타일로 나열하면 안 된다.

### 흑백 환경에서의 모자 구분

색 대신 **라벨 + 보더 스타일 + 스와치 패턴**으로 구분한다 (`wireframe.css` 의 `.hat--*`).

| 모자 | 보더 | 스와치 |
|---|---|---|
| 하양 | 1px solid `--c-4` | 빈 사각 |
| 빨강 | 1px dashed `--c-2` | 사선 |
| 검정 | 2px solid `--c-0` | 채움 |
| 노랑 | 1px dotted `--c-2` | 점 |
| 초록 | 3px double `--c-2` | 격자 |
| 파랑 | 좌측 4px solid `--c-0` | 가로줄 |

## 토론 진행 구조 (핵심 도메인 규칙)

**화면의 기본 단위는 "발언"이 아니라 「라운드」다.** 한 라운드가 아래를 돈다.

```
파랑이 라운드 목적 선언 (확장 / 추가 / 제거 / 검증 …)
  └ 발언 모자 5개가 순차 발언 (순서는 매 라운드 다름)
      └ 라운드 말 채점 — 살아있는 아이디어 전부, 축마다 담당 모자 하나
          └ 파랑의 정리 — 새로 알게 된 것 / 일어난 일 / 지금 풀 / 다음 후보
              └ [사용자 개입 지점] 방향을 틀거나 계속
```

- **라운드 1은 씨앗**: 5개 모자가 아이디어를 하나씩 내고, 채점 후 최하위 하나가 탈락한다.
  **의무 탈락은 이 1회뿐이다.**
- **라운드 2부터는 파랑이 라운드를 자유 설계**한다. 고정된 유형표가 없으므로
  **화면에 라운드 유형을 하드코딩하지 않는다.** 파랑이 선언한 목적을 그대로 받아 표시한다.
- **탈락하는 것은 아이디어다.** 모자는 여섯 다 끝까지 남는다. 모자 탈락 UI를 만들지 않는다.
- 아이디어는 **공용 풀**에 있고 특정 모자에 귀속되지 않는다. 라운드 2부터 화면에
  제안자를 표시하지 않는다 (계보 화면 R1에서만 표시).
- 종료는 **파랑 제안 + 사용자 승인**. 최대 6라운드.

### 아이디어의 표기

- **짧은 이름(2~5자)** 으로 부른다. 긴 이름은 표·요약·본문에 반복되며 화면을 잡아먹는다.
- 상태는 셋: **생존 / 탈락 / 병합**. 병합은 탈락이 아니므로 다르게 표기한다
  (탈락은 취소선, 병합은 흡수된 곳을 화살표로).

## 화면 위계 규칙 (실측 근거 있음)

**무엇을 크게 보여줄지의 순서다. 이 순서를 뒤집으면 화면이 실패한다.**

| 순위 | 무엇 | 왜 |
|---|---|---|
| 1 | **이번 라운드에 새로 알게 된 것** | 사용자가 이 서비스를 쓰는 이유. 2~4개 |
| 2 | **아이디어가 어떻게 바뀌었나** | 탈락·병합·진화. 변화가 없으면 라운드가 헛돈 것 |
| 3 | **파랑의 정리** | 지금 무슨 일이 있었는지. 한눈에 들어와야 한다 |
| 4 | 모자들의 발언 본문 | 근거. 접혀 있어도 된다 |
| 5 | **점수** | 파랑이 라운드를 설계하는 내부 도구. **기본 접힘** |

**점수 규칙이 옛 규약에서 뒤집혔다.** 옛 문서는 "점수는 화면의 핵심 요소이므로 그대로
노출한다"고 적었으나, 스킬 단계 검증에서 사용자가 **"점수는 사실 내가 보는 게 중요하지
않다. 아이디어 확장 과정을 보고 더 깊은 결과를 얻는지가 중요하다"** 고 판정했다
(2026-08-02). 점수를 전면에 두면 사용자는 아이디어가 어떻게 변했는지를 못 본다.

- 점수는 **접힌 영역**에 둔다. 펼치면 라운드당 표 하나(행=아이디어, 열=6축+합계+변화).
- 접힌 상태에서 보이는 것은 **변화량뿐**이다 (예: `인덱스 +0.95`). 절대값은 감춘다.
- **파랑의 정리에 점수를 섞지 않는다.**

## 사용자 개입 — 이 서비스의 핵심

라운드 사이가 사용자가 방향을 틀 수 있는 **유일한 지점**이다. 화면에서 이 지점이
약하면 사용자는 관객이 된다.

스킬 검증에서 사용자가 "깊이 파라"를 직접 지적해야 했다 (2026-08-02). **그 요구가
화면에 버튼으로 있었어야 했다.** 개입 수단을 자유 입력 하나로만 두지 않는다.

최소 개입 수단:

| 수단 | 무엇을 바꾸나 |
|---|---|
| 계속 | 파랑이 제안한 다음 라운드를 그대로 연다 |
| 라운드 방향 지정 | 다음 라운드 목적을 사용자가 고른다 (깊이 파기 / 새 아이디어 / 정리 / 공격) |
| 아이디어 지목 | 특정 아이디어를 다음 라운드의 대상으로 지정 |
| 자유 발언 | 위로 표현 안 되는 제약·사실을 넣는다 |
| 종료 | 지금까지로 보고서를 받는다 |

**사용자 개입은 이미 매겨진 점수를 바꾸지 않는다.** 다음 라운드 설계에만 반영된다.

## 데이터 토큰

사용자 데이터는 중괄호 토큰 + `.token` 클래스로 표기한다. 동일 의미는 동일 표기.

`{주제}` `{라운드목적}` `{발언}` `{아이디어}` `{알게된것}` `{근거}` `{정리}` `{계보}`
`{날짜}` `{소요시간}` `{모자}` `{출처}`

- `{알게된것}` — 이번 라운드의 산출물 한 줄. 화면 위계 1순위.
- `{발언}` — 모자 발언 본문 블록 하나. 한 발언에 1~3개가 붙는다.
- `{근거}` — 점수가 움직인 이유 한 줄. 접힌 영역 안에만 등장한다.
- **점수는 토큰을 쓰지 않는다.** 0~10 정수와 가중합(소수점 둘째 자리)이 확정 스케일이므로
  대표 숫자를 직접 적는다.

## 비공개 필드 — 화면 노출 금지

- 프롬프트 원문
- 모델명, 토큰 수, 비용
- 발언 순서 결정 로직 (순서는 매 라운드 달라지지만 그 이유를 노출하지 않는다)
- 채점 대행 여부의 내부 판정 과정 (결과 표기 "(대행)"만 노출)

## 카피 규칙

- 라벨·수치 중심, **2~3단어**. 설명하려 하지 말고 구조로 전달한다
- 서술형·과잉 친절체 금지: "~하고 있어요", "~해 주세요", "당신만의 ~"
- 이모지·느낌표·감탄사 금지
- lorem ipsum 금지 — 실제 도메인 라벨만

### 상태 카피 고정

| 상태 | 카피 |
|---|---|
| 파랑이 라운드 설계 중 | `설계 중` |
| 모자 발언 생성 중 | `생성 중` |
| 하양이 검색 중 | `검색 중` |
| 채점 중 | `채점 중` |
| 파랑 정리 중 | `정리 중` |
| 대기 | `대기` |
| 사용자 차례 | `내 차례` |
| 라운드 완료 | `완료` |
| 검색 실패 | `검색 실패` + `[다시]` |
| 사실 미발견 | `확인 필요` |
| 오류 | `실패` + `[다시]` |

「검색 실패」와 「확인 필요」는 다른 상태다. 전자는 도구가 실패한 것이고 후자는 검색은
됐지만 원하는 사실이 없는 것이다. 화면에서 합치지 않는다.

## 작업 절차

새 화면: 기존 화면 전수 읽기 → 4안(`{ID}-options.html`) → 선택 → 확정(`{ID}.html`)
→ 사이드 노트(의도/대안/미정) → `index.html` 갱신 → **인접 화면 [다음] 메타 역방향 갱신**

메타는 항상 양방향으로 일치해야 한다. 한쪽에만 적혀 있으면 안 된다.

작성·수정 직후 브라우저로 띄워 **375×812 / 768×1024 / 1280×900** 3종을 함께 확인한다.
