약점
모바일에서 가로 스크롤 필수. 의견 본문이 격자 밖으로 밀린다.

의도

  • 기본 단위를 의견으로 바꿨다. 모자가 순서대로 말하는 화면이 아니라, 의견 하나가 평가받고 점수가 매겨지는 화면이다.
  • 네 안은 5개 평가와 파랑 점수의 위계에서 갈린다. A는 둘 다 펼침 / B는 파랑만 먼저 / 실험 A는 의견 간 비교 우선 / 실험 B는 관점별 차이 우선.
  • 파랑 점수는 어느 안에서도 5개 평가와 같은 줄에 두지 않았다. 평균으로 읽히면 안 되므로 .verdict 로 분리하고 "평균·합계·총점" 라벨을 쓰지 않았다.
  • 점수 스케일이 미정이라 숫자를 박지 않고 막대 + 토큰으로 표현했다. 스케일이 정해지면 막대 옆 토큰만 숫자로 바뀐다.
  • 의견 제시 순서를 초록 → 하양 → 검정으로 그렸다. 순서가 실행마다 달라진다는 규칙을 와이어에서도 드러내려고 하양부터 시작하지 않았다.
  • 자기 의견에는 자기가 평가하지 않으므로 해당 칸을 — 로 비웠다.

대안

  • 이전 4안(순차 스트림 / 라운드 보드 / 한 장씩 / 수집 보드) — 발언 나열이 전제라 평가·점수 구조가 들어갈 자리가 없어 전부 폐기.
  • 파랑 점수를 5개 평균 막대와 나란히 비교 표시 — 평균으로 오해될 소지가 커서 제외.
  • 탈락 UI(모자 제외) — 아직 고민 중인 사항이라 어느 안에도 넣지 않음.

미정

  • 점수 스케일 — 0~10 / 0~100 / 5점 척도. 확정되면 막대 옆 표기가 정해진다.
  • 평가에 한 줄 근거가 항상 붙는지, 점수만 있는지 (보편 A는 있음 전제, 실험 A는 없음 전제)
  • 모자당 의견 1~2회 중 2회째를 언제 내는지 — 한 바퀴 후인지 연속인지
  • 사이클 종료 조건, 모자 탈락 여부 — 정해지면 확정안에 상태 추가
  • 사용자 발언이 점수를 바꾸는지, 다음 의견에만 반영되는지
  • 오류(평가 실패) 상태 표현 — 확정안에서 상태 프레임으로 추가
