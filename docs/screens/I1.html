삭제 확정

의도

  • 첫 화면이 목록인 이유. 토론은 최대 6라운드이고 라운드 사이마다 멈춘다. 실제 검증에서도 여러 번 끊겼다. 그러면 첫 화면의 일은 "새로 시작"이 아니라 이어하기다.
  • 「내 차례」가 가장 강한 신호. 파랑이 종료를 제안했거나 확인 질문을 던져둔 방이다. 이 표시가 없으면 방치된 토론이 그대로 죽는다.
  • 진행도를 R3/6 로 표기. 최대 6라운드라는 안전장치가 목록에서부터 보인다. 끝이 없는 대화가 아니라는 것.
  • 빈 목록은 보편 A를 흡수. 첫 사용자에게 빈 목록을 보이면 아무 정보가 없다. 파랑이 말을 걸고 유형 칩을 준다.
  • 하단 입력창은 항상 있다. 목록을 보다가 새 주제가 떠오르면 그 자리에서 던진다. 「+ 새로」 버튼으로 화면을 하나 더 거치지 않는다.

대안

  • 주제 심사(실험 A) — 6모자가 값을 못 낼 주제를 거르는 안. 폐기하지 않고 I2로 옮긴다. 파랑이 확인 질문을 던지는 자리에서 "이 주제는 관점이 안 갈립니다"를 말하는 편이 목록 화면에서 문지기를 세우는 것보다 낫다.
  • 모자들이 기다리는 안(실험 B) — 정체성을 첫 화면에서 체감시키지만 재방문 시 소음이 된다. 빈 목록 상태에 일부만 남길 수 있다.
  • 「+ 새로」 버튼으로 입력 화면을 따로 두는 안 — 탭이 하나 늘어 폐기.

확정 (2026-08-04 영속화 결정으로 해소)

  • 중단된 토론의 수명 — 무기한. 로컬 SQLite에 대화 전문 + 라운드별 상태 스냅샷을 무기한 보관하므로, 얼마나 오래 멈췄든 스냅샷으로 재개한다. 목록에서 수명 표시·만료 처리가 필요 없다.

확정 (2026-08-15 화면 설계로 해소)

  • 완료된 토론의 자리 — 분리가 아니라 접기. 탭·화면을 늘리면 전환이 I1 밖으로 새므로, 목록 하나에 「진행 중」을 위로 두고 완료는 완료 N 폴드로 접는다. 무기한 보관으로 완료가 무한히 쌓여도 접힌 한 줄이다. 펼치면 완료 카드가 시간순으로 나온다.
  • 삭제·이름 변경 — 길게 누름 시트. 목록 카드를 길게 누르면 이름 변경 / 내보내기 / 삭제 시트가 뜬다. 스와이프 액션은 발견이 안 되고, 카드마다 버튼을 박으면 목록이 무너진다. 삭제는 무기한 보관 원칙의 유일한 예외라 시트 안에서 2단계 확인(즉시·복구 불가 명시)을 거친다. 내보내기는 완료 전이라도 지금까지의 전문을 Markdown으로 준다.
  • 주제 심사 — I2 확인 질문 전. I2로 넘어갔던 미정이 해소됐다 (I2 상태 4 참조). 파랑이 주제를 받자마자 심사하고, 통과면 아무 말 없이 첫 질문으로 간다 — 답을 받은 뒤 무르는 것보다 싸다.
