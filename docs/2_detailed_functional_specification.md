# **2. 상세 기능 명세 (Detailed Functional Specification)**

**참조 문서**: [docs/0_architecture.md](docs/0_architecture.md), [docs/1_goal_scope_definition.md](docs/1_goal_scope_definition.md)

## **2.1 핵심 AI 기능**

### **FEAT-001: 의도 분류 시스템**
- **기능 설명**: 사용자 입력을 분석하여 단순 질문과 복합적 사고가 필요한 질문을 구분
- **트리거**: 사용자가 질문을 입력하고 전송 버튼을 클릭
- **처리 절차**:
  1. 사용자 입력 텍스트 수신
  2. 의도 분류 모델을 통한 질문 유형 판별
  3. 단순 질문(인사, 정체성 문의) → 간단 답변 반환
  4. 복합 질문(문제 해결, 아이디어 확장) → 6모자 토론 시스템 라우팅
- **성공 조건**:
  - 의도 분류 정확도 90% 이상
  - 응답 시간 2초 이내
- **실패 조건**:
  - 분류 실패 시 기본적으로 6모자 시스템으로 라우팅
  - 시스템 에러 시 "죄송합니다, 답변을 생성하지 못했습니다" 메시지 출력

### **FEAT-002: 6개 모자 에이전트 시스템**
- **기능 설명**: 각 색깔 모자별 특화된 AI 에이전트가 순차적으로 사용자 질문에 대해 토론
- **트리거**: 의도 분류에서 복합 질문으로 판별된 경우
- **처리 절차**:
  1. **하얀 모자**: 객관적 정보와 사실 분석
     - 사용자 질문에서 확인 가능한 사실 수집
     - 필요한 추가 정보 식별
     - 가정과 사실 구분
  2. **빨간 모자**: 감정과 직관 표현 (하얀 모자 답변 참조)
     - 질문에 대한 직감적 반응
     - 감정적 측면 고려
     - 인간적 요소 반영
  3. **검은 모자**: 위험과 비판적 분석 (이전 모든 답변 참조)
     - 잠재적 문제점과 위험 요소 식별
     - 약점과 한계 분석
     - 실패 가능성 검토
  4. **노란 모자**: 긍정적 측면과 기회 발굴 (이전 모든 답변 참조)
     - 장점과 이점 발견
     - 긍정적 결과 예측
     - 실행 가능성 모색
  5. **초록 모자**: 창의적 아이디어와 대안 제시 (이전 모든 답변 참조)
     - 새로운 관점과 아이디어 생성
     - 기존 틀을 벗어난 대안 제시
     - 브레인스토밍 수행
  6. **파란 모자**: 전체 토론 관리 및 품질 검증 (모든 모자 답변 종합)
     - 토론 흐름 정리
     - 답변 품질 평가
     - 최종 종합 결론 도출
- **성공 조건**:
  - 모든 모자가 각자의 역할에 맞는 답변 생성
  - 파란 모자의 품질 검증 통과
- **실패 조건**:
  - 품질 검증 실패 시 재순환 (최대 3회)
  - 3회 실패 시 현재까지의 답변으로 종료

### **FEAT-003: 품질 검증 및 재순환 시스템**
- **기능 설명**: 파란 모자가 토론 품질을 평가하여 재토론 필요성 판단
- **트리거**: 파란 모자의 최종 종합 단계
- **처리 절차**:
  1. 파란 모자가 다음 기준으로 품질 평가
     - 사용자 질문에 대한 답변 완성도
     - 각 모자별 관점의 충분한 반영
     - 논리적 일관성과 종합성
  2. 품질 검증 통과 → 최종 답변 생성
  3. 품질 검증 실패 → 재토론 시작
     - 부족한 부분을 명시한 확장 쿼리 생성
     - 모자 순서 변경하여 재토론 진행
- **성공 조건**:
  - 1차 품질 통과율 80% 이상
  - 재순환 시 품질 개선 확인
- **실패 조건**:
  - 3회 재순환 후에도 품질 기준 미달 시 현재 상태로 종료

### **FEAT-004: LangGraph 워크플로우 엔진**
- **기능 설명**: 상태 기반 그래프 구조로 에이전트 간 순서와 조건부 라우팅 관리
- **트리거**: 6모자 토론 시스템 시작
- **처리 절차**:
  1. StateGraph 초기화 및 상태 객체 생성
  2. 각 모자별 노드 정의 및 LLM 연결
  3. 조건부 엣지를 통한 다음 노드 라우팅
  4. 체크포인터를 통한 중간 상태 저장
  5. 최종 노드 도달 시 결과 반환
- **성공 조건**:
  - 그래프 실행 오류 없음
  - 상태 저장/복구 정상 동작
- **실패 조건**:
  - 그래프 실행 중단 시 체크포인트에서 복구 시도

## **2.2 데이터 처리 기능**

### **FEAT-005: 대화 상태 관리**
- **기능 설명**: 전체 토론 과정의 상태를 중앙 집중적으로 관리
- **트리거**: 토론 세션 시작
- **처리 절차**:
  1. 세션 고유 ID 생성
  2. 상태 객체 초기화 (사용자 질문, 모자별 답변, 진행 상황)
  3. 각 모자 실행 시마다 상태 업데이트
  4. PostgreSQL에 체크포인트 저장
  5. Redis에 세션 캐시 저장
- **성공 조건**:
  - 상태 정합성 보장
  - 데이터 손실 없음
- **실패 조건**:
  - 데이터베이스 연결 실패 시 메모리 임시 저장

### **FEAT-006: 토론 기록 저장 및 조회**
- **기능 설명**: 완료된 토론의 전체 기록을 구조화하여 저장
- **트리거**: 토론 완료 또는 사용자의 기록 조회 요청
- **처리 절차**:
  1. 토론 완료 시 전체 대화 기록 정리
  2. 각 모자별 기여도와 핵심 인사이트 추출
  3. 구조화된 JSON 형태로 데이터베이스 저장
  4. 사용자 요청 시 기록 조회 및 반환
- **성공 조건**:
  - 모든 토론 기록 정상 저장
  - 조회 시 데이터 무결성 보장
- **실패 조건**:
  - 저장 실패 시 임시 세션 메모리에 보관

## **2.3 사용자 인터페이스 기능**

### **FEAT-007: 그룹 채팅 형태 UI**
- **기능 설명**: 6개 아바타가 순차적으로 발언하는 채팅 인터페이스
- **트리거**: 앱 실행 및 메인 화면 진입
- **처리 절차**:
  1. 6개 모자별 아바타 표시 (색깔별 구분)
  2. 사용자 입력창 제공
  3. 토론 진행 시 각 모자별 메시지 버블 표시
  4. 현재 발언 중인 모자 강조 표시
  5. 스크롤 자동 이동으로 최신 메시지 추적
- **성공 조건**:
  - 직관적이고 명확한 인터페이스
  - 모자별 구분 명확성
- **실패 조건**:
  - UI 렌더링 오류 시 텍스트만 표시

### **FEAT-008: 실시간 스트리밍 표시**
- **기능 설명**: SSE를 통해 각 모자의 답변을 실시간으로 화면에 표시
- **트리거**: 토론 시작 및 각 모자의 답변 생성
- **처리 절차**:
  1. SSE 연결 수립
  2. 백엔드에서 각 모자 답변 완료 시 이벤트 전송
  3. 클라이언트에서 이벤트 수신 및 UI 업데이트
  4. 타이핑 애니메이션 효과 적용
  5. 답변 완료 시 다음 모자로 진행 표시
- **성공 조건**:
  - 실시간 업데이트 정상 동작
  - 네트워크 끊김 시 자동 재연결
- **실패 조건**:
  - SSE 연결 실패 시 폴링 방식으로 대체

### **FEAT-009: 세션 코인 관리**
- **기능 설명**: 무인증 환경에서 세션당 5코인 제공 및 사용량 추적
- **트리거**: 앱 첫 실행 및 새 세션 시작
- **처리 절차**:
  1. 세션 시작 시 5코인 할당
  2. 질문 입력 시마다 1코인 차감
  3. 잔여 코인 수 실시간 표시
  4. 코인 소진 시 새 세션 안내
- **성공 조건**:
  - 정확한 코인 차감 및 표시
  - 코인 부족 시 적절한 안내
- **실패 조건**:
  - 코인 관리 오류 시 기본 5회 제한 적용

## **2.4 통신 및 연동 기능**

### **FEAT-010: Server-Sent Events (SSE) 통신**
- **기능 설명**: 서버에서 클라이언트로의 실시간 데이터 스트리밍
- **트리거**: 토론 시작 및 모바일 앱 연결
- **처리 절차**:
  1. 클라이언트가 SSE 엔드포인트에 연결
  2. 서버에서 토론 진행 상황을 이벤트로 전송
  3. 클라이언트에서 이벤트 스트림 수신 및 처리
  4. 연결 끊김 시 자동 재연결 시도
- **성공 조건**:
  - 안정적인 실시간 통신
  - 자동 재연결 기능 정상 동작
- **실패 조건**:
  - 연결 실패 시 HTTP 폴링으로 대체

### **FEAT-011: LangChain Tool 통합**
- **기능 설명**: 필요시 웹검색, 정보 수집 등의 외부 도구 활용
- **트리거**: 모자별 답변 생성 중 추가 정보가 필요한 경우
- **처리 절차**:
  1. 각 모자 LLM이 Tool 사용 필요성 판단
  2. 적절한 Tool 선택 (웹검색, MCP Server 등)
  3. Tool 실행 및 결과 획득
  4. 결과를 답변에 통합하여 최종 응답 생성
- **성공 조건**:
  - Tool 실행 정상 동작
  - 관련성 높은 정보 수집
- **실패 조건**:
  - Tool 실행 실패 시 기본 지식으로 답변 생성

## **2.5 에러 처리 및 복구 기능**

### **FEAT-012: 실패 처리 및 복구 전략**
- **기능 설명**: 시스템 오류 발생 시 적절한 복구 및 사용자 안내
- **트리거**: LLM 호출 실패, 네트워크 오류, 시스템 에러 발생
- **처리 절차**:
  1. 에러 유형 분류 (네트워크, LLM, 시스템)
  2. 재시도 가능한 에러의 경우 자동 재시도 (최대 3회)
  3. 재시도 불가능한 에러의 경우 사용자에게 안내 메시지
  4. 부분 응답이 있는 경우 기존 답변 보존
  5. 체크포인트에서 세션 복구 시도
- **성공 조건**:
  - 적절한 에러 메시지 제공
  - 가능한 범위에서 서비스 지속
- **실패 조건**:
  - 복구 불가능한 경우 새 세션 시작 안내

## **2.6 성능 및 품질 보장 기능**

### **FEAT-013: 응답 시간 최적화**
- **기능 설명**: 각 모자별 답변 생성 시간을 30초 이내로 제한
- **트리거**: 모자별 LLM 호출 시작
- **처리 절차**:
  1. 각 LLM 호출에 타임아웃 설정 (30초)
  2. 프롬프트 길이 최적화로 처리 시간 단축
  3. 병렬 처리 가능한 부분 식별 및 적용
  4. 응답 시간 모니터링 및 로깅
- **성공 조건**:
  - 95% 요청이 30초 이내 응답
  - 전체 토론 시간 15분 이내
- **실패 조건**:
  - 타임아웃 발생 시 부분 답변 제공

### **FEAT-014: 동시 접속 처리**
- **기능 설명**: 여러 사용자의 동시 토론 세션 지원
- **트리거**: 다수 사용자의 동시 접속
- **처리 절차**:
  1. 세션별 독립적인 상태 관리
  2. 리소스 풀링을 통한 효율적 LLM 호출
  3. 로드 밸런싱으로 서버 부하 분산
  4. 큐 시스템으로 요청 순서 관리
- **성공 조건**:
  - 100명 동시 접속 안정적 처리
  - 세션 간 간섭 없음
- **실패 조건**:
  - 과부하 시 대기열 안내 메시지 제공
