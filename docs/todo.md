## 1. 사용자 결정 — 2026-08-04 전부 결정됨

### 1-1. 챗봇 영속화 계층 — 확정

**로컬 SQLite · 무기한 보관 · 대화 전문 + 라운드별 상태 스냅샷(살아있는 풀·점수
이력·계보·보류 항목) 둘 다 저장.** 재개는 스냅샷으로, 열람은 전문으로. 서버 저장은
공유 기능이 필요해질 때 재검토.

이 결정으로 묶여 있던 화면 미정 3건이 풀렸다:

- I1 「중단된 토론의 수명」 — **해소.** 무기한 보관이므로 수명 개념 자체가 없다
- I1 「완료된 토론의 자리」 — **막힘 해제.** 자동 삭제로는 못 풀게 됐고, 분리/접기의
  순수 화면 설계 문제가 됐다 (→ 2장)
- R1 「내보내기 형식」 — **Markdown 확정.** 로컬 저장이라 링크 공유는 성립하지 않는다

### 1-2. 「모자 지목」 — 기능 제거로 확정

규칙(파랑 검토 후 반영)과 버튼 기대(즉시 발언)의 충돌을 **칩 제거**로 해소했다.
특정 모자의 의견이 필요하면 자유 발언으로 쓰면 파랑이 라운드 설계에 반영한다.
D1.html에서 칩과 미정 항목을 제거했다 (2026-08-04).

### 1-3. MCP 착수 시점 — 챗봇이 완벽하게 동작한 뒤

**챗봇 → MCP 순서 확정. 스킬은 실패로 종결** (2026-08-04 사용자 결정).
tool 후보 목록은 [tool-ideas.md](tool-ideas.md), 1순위는 채점 기록·집계 tool.
그 핵심인 **"이미 낸 점수의 소급 수정 불가"** 는 코드가 기록을 쥐어야 성립한다.
채점 기록은 챗봇 DB 스키마의 일부이므로, 영속화 스키마 설계 때 tool 계약과 같은
구조를 쓴다.
