## 1. 사용자 결정이 필요한 것

**임의로 정하지 말 것.** 아래는 답에 따라 여러 화면이 동시에 바뀐다.

### 1-1. 챗봇 영속화 계층 — 가장 많이 막고 있음

토론 상태를 어디에 얼마나 오래 보관하는가. 이것이 안 정해져서 **화면 미정 3건이
동시에 묶여 있다.**

- I1 「중단된 토론의 수명」 — 2주 전 라운드 1에서 멈춘 토론을 이어할 때 맥락이 살아 있나
- I1 「완료된 토론의 자리」 — 계속 쌓이면 이어할 방이 묻힌다
- R1 「내보내기 형식」 — Markdown / PDF / 링크

정해야 할 것: **저장 위치**(로컬 / 서버) · **보관 기간** · **무엇까지 저장하나**
(대화 전문인가, 라운드별 상태 요약인가).

### 1-2. 「모자 지목」의 강제력 — 규칙과 화면이 어긋남

D1에서 사용자가 "초록 지목"을 누르면 어떻게 되는가.

| | 동작 | 문제 |
|---|---|---|
| 도메인 규칙 | 파랑이 검토해 다음 라운드 설계에 **반영** | 화면상 기대와 다름 — 눌렀는데 안 나오면 고장으로 보인다 |
| 화면 기대 | 즉시 그 모자가 발언 | 파랑 지휘형이 무너진다 |

**둘 중 하나를 고르거나, 버튼 문구를 기대에 맞게 바꿔야 한다**(예: "초록 지목" →
"초록 의견 요청"). 지금은 규칙과 화면이 서로 다른 말을 한다.

### 1-3. MCP 단계 커스텀 tool — 착수 시점 미정

후보 목록은 [tool-ideas.md](tool-ideas.md). 1순위는 채점 기록·집계 tool이며,
그 핵심인 **"이미 낸 점수의 소급 수정 불가"** 는 코드가 기록을 쥐어야 성립한다.
스킬 단계에서 못 푼 자기일관성 편향의 유일한 처방이다.

## 2. 결정 없이 진행할 수 있는 것

- **D2 개입 상세** — D1의 개입 수단을 펼친 화면. 단 1-2가 정해져야 완결된다
- **H1 토론 기록** — I1 목록과 겹치는 부분이 크다. 별도 화면이 필요한지부터 검토
- **S1 설정** — 모델·검색 사용 여부 등. 비공개 필드(모델명·비용) 노출 금지 규칙에 걸림
- **반응형 확인** — 지금까지 375 기준으로만 그렸다. 768 / 1280 을 실제로 띄워 확인.
  특히 D1·R1의 1024 이상 레이아웃은 "단일 컬럼 확대"로 두었고 우측 고정 패널 안이 미결
- **I1 목록 항목 관리** — 삭제·이름 변경 동작이 없다
