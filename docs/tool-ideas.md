# 토론용 도구(tool) 아이디어

2026-07-29, 10개 주제 병렬 검증에서 관찰된 약점을 근거로 정리.
현재 모자들에게 맡긴 도구는 **웹 검색뿐**이며, 아래는 후보 목록이다.
MCP 단계의 커스텀 tool 설계(미확정 사항)의 원천 자료.

## 우선순위 1 — 관찰된 약점을 직접 해결

### 1. 채점 기록·집계 도구 ★ MCP 첫 커스텀 tool 후보

- **해결하는 약점**: 자기일관성 편향 (점수가 서사를 따라감 — 10회 검증에서 최종
  가중합이 7.65~8.50 좁은 구간에 몰림), 가중합 암산 오류.
- **동작**: 각 모자가 점수를 매기는 즉시 기록 → 가중합은 코드가 계산 →
  이미 낸 점수의 소급 수정 불가 → 라운드별 점수 흐름 자동 추적.
- **단계별**: 스킬 = Python 실행으로 흉내 가능 / MCP = `record_score` ·
  `get_scoreboard` tool로 정식화 / 챗봇 = DB 기록.
- LLM이 못하는 것(산술·기록 무결성)을 도구가 맡는 정석 설계.

### 2. 계산·추정 도구 (코드 실행)

- **해결하는 약점**: 하양·노랑의 수치 근거가 전부 LLM 암산이었음
  (손익분기 역산, 페르미 추정 등).
- **사용 모자**: 하양(사실 검증), 노랑(실행가능성 근거).

### 3. 발언 순서·지명 난수 도구

- **해결하는 약점**: "매 실행 순서 변경" 규칙을 LLM 자의에 맡기면 그럴듯한
  순서로 수렴함 (R2가 9/10 검증으로 고정된 관성 포함).
- **동작**: 진짜 난수로 순서·지명 후보를 뽑고 파랑이 채택/조정.

## 우선순위 2 — 실용 가치 큼

### 4. 사용자 자료 읽기 (파일/문서)

- 사용자가 기획서·데이터·코드를 주면 **하양이 반드시 읽는다**.
- 스킬 단계에서는 Read 도구가 이미 있으므로 스킬 문서에 규칙 한 줄이면 됨.

### 5. 토론 상태 저장 (계보·보류 항목 기록)

- 긴 토론에서 계보·보류 항목의 컨텍스트 유실 방지. 라운드마다 상태를 기록.
- **챗봇 단계 영속화 설계(미확정 사항)의 원형.** MCP = `save_state` / `load_state`.

## 우선순위 3 — 주제 유형별 옵션 팩

### 6. 특화 검색

- 학술(arXiv/PubMed — 교육·건강 주제), 뉴스, 시장 데이터, 지도/상권(창업 주제).
- 일반 웹 검색 대비 하양의 근거 품질 상승. MCP 단계에서 옵션으로.

### 7. 이미지 생성 (초록의 컨셉 시각화)

- 재미 요소. 점수·수렴 기여가 적어 후순위.
