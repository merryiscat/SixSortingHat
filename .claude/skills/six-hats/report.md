# 최종 보고서 형식

**여섯 모자와 파랑이 함께** 작성한다. 각 모자는 자기 모드에서 본 것을, 파랑은 전체
균형과 구조를 책임진다. 탈락·병합된 아이디어의 기여를 빠뜨리면 보고서가 아니라
살아남은 하나의 소개문이다.

## 구조

```
# 사고 확장 보고서: {주제}

## 1. 주제의 여정
처음 질문이 확인 질문과 라운드를 거치며 어떻게 확정·재정의되었는가. 2~4문장.
개시 확인 질문에서 사용자의 답이 방향을 바꿨다면 그것을 명시한다.

## 2. 아이디어 계보
씨앗들이 라운드를 거치며 어떻게 변했는가 — 라운드별로 무엇이 탈락·병합·추가·확장
되었고 그 판단의 근거는 무엇이었는지. 파랑이 각 라운드를 어떤 방식(확장·추가·제거·
검증 등)으로 설계했는지도 남긴다.
병합된 아이디어는 최종안의 어느 부분으로 살아남았는지 짚는다.

## 3. 최종안
살아남은 아이디어. 무엇을 하는 것인지, 왜 이것이 남았는지.
마지막 라운드의 축별 점수와 가중합을 표기.
**여럿이 남았으면 파랑이 우선순위를 매기고 그 근거를 밝힌다** — 나열만 하고
끝내지 않는다.

## 4. 관점별 기여
모자 6개 각각이 이 결론에 무엇을 보탰는가. 한 모자당 1~2개.
어느 라운드였는지 표기. **여섯 모두를 다룬다** — 빠진 모자가 있으면 그 자체가
관점 편중의 신호다.

## 5. 위험과 남은 약점
검정의 기여를 중심으로, 최종안이 안고 있는 위험.
탈락한 아이디어가 피하고 있었는데 최종안은 안고 가는 위험이 있다면 반드시 적는다.

## 6. 다음 단계
사용자가 바로 할 수 있는 행동 3~5개. 확인이 필요한 열린 질문 2~3개.
가장 위험한 가정을 가장 싸게 검증할 방법이 무엇인지 먼저 적는다.
```

## 규칙

- 토론에 실제로 나온 것만 쓴다. 보고서 단계에서 새 아이디어를 지어내지 않는다.
  (단, 4장의 관점별 기여 정리와 파랑의 균형 판단은 종합이므로 예외.)
- 점수를 인용할 때는 **가중합**을 쓰고, 어느 라운드 시점인지 밝힌다.
  같은 아이디어라도 라운드마다 점수가 달라지므로 시점 없는 인용은 오해를 만든다.
- 검색으로 확인한 사실은 출처를 유지한다.
- 제안자 표기는 **2장 계보에서만** 쓴다. 3~6장에서는 아이디어 이름으로 부른다.
  최종안을 "누구의 안"으로 부르면 소유권 분리 원칙이 마지막에 무너진다.
- 분량은 전체 토론의 1/3을 넘지 않는다. 보고서는 요약이지 재방송이 아니다.
