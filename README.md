# SixSortingHat - 육모자 사고 확장 앱

## 개요
여섯 색깔 모자 기법은 세계적인 컨설턴트이자 창의성 분야의 권위자인 에드워드 드 보노(Edward de Bono)가 개발한 사고 기법입니다. 
이 기법은 복잡한 문제에 대해 여러 사람이 동시에 다른 관점에서 생각하며 발생하는 비효율과 갈등을 방지하고, 
특정 시점에는 하나의 관점에만 집중하여 논의를 진행함으로써 보다 명료하고 생산적인 결과를 도출하기 위해 고안되었습니다.

참가자들은 여섯 가지 색깔로 구분된 가상의 '사고 모자'를 번갈아 쓰는 상징적인 행위를 통해, 
각 모자가 대표하는 특정 유형의 사고에만 집중하게 됩니다. 이를 통해 개인의 성향이나 감정에 치우치지 않고, 주제에 대한 다각적이고 균형 잡힌 탐색이 가능해집니다.

### 각 색깔의 모자는 다음과 같은 고유한 사고의 방향을 나타냅니다.
#### 하얀 모자 (White Hat): 정보와 사실
역할: 객관적인 정보와 데이터에 집중합니다.
주요 질문: "우리가 무엇을 알고 있는가?", "어떤 정보가 필요한가?", "이것은 사실인가, 아니면 가정인가?"
특징: 감정이나 의견을 배제하고 중립적인 입장에서 사실과 수치를 기반으로 사고합니다.

#### 빨간 모자 (Red Hat): 감정과 직관
역할: 직감, 감정, 예감 등 주관적인 느낌을 표현합니다.
주요 질문: "이 문제에 대해 어떻게 느끼는가?", "나의 직감은 무엇을 말하고 있는가?"
특징: 논리적인 근거나 설명을 요구하지 않고, 순수한 감정의 표현을 허용합니다. 이를 통해 논의에 인간적인 요소를 더하고, 중요한 직관을 포착할 수 있습니다.

#### 검은 모자 (Black Hat): 위험과 비판
역할: 잠재적인 문제점, 위험, 약점, 부정적인 측면을 찾아냅니다.
주요 질문: "무엇이 잘못될 수 있는가?", "가장 큰 위험 요소는 무엇인가?", "이 계획의 약점은 무엇인가?"
특징: 논리적인 근거에 기반한 비판적 사고를 통해 신중한 판단을 돕습니다. '악마의 변호인' 역할을 수행하며 잠재적 실패 가능성을 줄입니다.

#### 노란 모자 (Yellow Hat): 긍정과 낙관
역할: 아이디어나 제안의 긍정적인 측면, 이점, 기회를 탐색합니다.
주요 질문: "이것의 장점은 무엇인가?", "어떤 긍정적인 결과가 기대되는가?", "어떻게 실행 가능하게 만들 수 있는가?"
특징: 밝고 긍정적인 시각으로 가치와 가능성을 발견하고, 아이디어를 발전시킬 동기를 부여합니다.

#### 초록 모자 (Green Hat): 창의성과 새로운 아이디어
역할: 기존의 틀에서 벗어나 새로운 아이디어, 대안, 가능성을 제시합니다.
주요 질문: "다른 방법은 없을까?", "전혀 새로운 아이디어가 있는가?", "이것을 다르게 보면 어떨까?"
특징: 창의적이고 모험적인 사고를 장려하며, 브레인스토밍과 같이 자유로운 아이디어 생성을 촉진합니다.

#### 파란 모자 (Blue Hat): 사고의 관리와 통제
역할: 전체적인 사고 과정을 관리하고 통제하는 사회자 역할을 합니다.
주요 질문: "우리의 논의 목표는 무엇인가?", "지금 어떤 모자를 써야 할까?", "다음 단계는 무엇인가?"
특징: 회의의 시작과 끝을 주관하며, 논의의 방향을 설정하고, 다른 모자들의 사용 순서를 결정합니다. 오케스트라의 지휘자처럼 전체적인 사고의 흐름을 조율합니다.

육모자 애플리케이션은 이 사고 기법을 사람이 아닌 LLM 이 활용하면 어떨까? 를 바탕으로 설계되고 기획 되었습니다.
6개의 LLM 모델이 각자의 역할을 받아 사고를 확장한다면 사용자는 더 많은 아이디어와 창의력을 가질 수 있지 않을까?
내가 보지 못한 시점을 육모자 애플리케이션을 통해 볼 수 있지는 않을까?

---

## 토론 방식 — 아이디어 탈락제 + 파랑 지휘형

위 여섯 역할 정의 위에, 이 프로젝트만의 진행 규칙이 얹혀 있습니다.

**탈락하는 것은 모자가 아니라 아이디어입니다.** 모자는 여섯 전부 끝까지 남습니다.

1. **확인 질문** — 파랑이 주제의 모호한 지점을 사용자에게 되묻고 주제를 확정합니다.
   이 관문을 건너뛰지 않습니다.
2. **라운드 1 (씨앗)** — 발언 모자 5개가 각자의 모드에서 아이디어를 하나씩 냅니다.
   채점 후 최하위 하나가 탈락하고, **이후 아이디어는 제안자와 분리**됩니다.
   의무 탈락은 이 한 번뿐입니다.
3. **라운드 2 이후 (파랑 지휘)** — 파랑이 매 라운드의 목적을 직접 설계합니다.
   확장(깊이 파기) · 추가(새 씨앗) · 제거(탈락·병합) · 검증(공격·사실 확인) 등.
4. **채점** — 축마다 담당 모자가 하나씩 붙습니다.
   근거 0.25(하양) / 실행가능성 0.20(노랑) / 위험 내성 0.20(검정) /
   주제 적합성 0.15(파랑) / 독창성 0.10(초록) / 호응 0.10(빨강).
5. **종료** — 파랑이 제안하고 사용자가 승인합니다 (최대 6라운드).
   여섯 모자와 파랑이 함께 최종 보고서를 씁니다.

**왜 모자가 아니라 아이디어를 탈락시키는가.** 초기 설계는 모자를 하나씩 탈락시켰습니다.
그런데 공통 채점표를 모자에 적용하니 모자들이 그 척도로 수렴해 서로 닮아버렸습니다 —
감정을 대변해야 할 빨강이 UI 설계 처방을 냈습니다. 6모자의 가치는 관점의 차이인데
그 차이가 지워진 것입니다. 여섯 관점을 다 쓰자는 기법에서 관점을 죽이는 것 자체가
취지와도 충돌합니다. 그래서 탈락 대상을 아이디어로 바꿨습니다.

## 세 가지 형태

같은 사고 엔진을 세 가지 방식으로 전달합니다. 가르는 기준은 **"LLM 호출을 누가 하는가"** 입니다.

| 형태 | 오케스트레이션 주체 | 소비자 | 상태 |
|---|---|---|---|
| **스킬** (Claude Skill) | Claude 자신 | Claude 세션 내부 | 완성 (최근 규칙 보강분은 재검증 예정) |
| **MCP 서버** | 호출한 클라이언트의 LLM | 임의의 MCP 클라이언트 | 미착수 |
| **챗봇** | 자체 코드 | 최종 사용자 | 미착수 |

스킬로 도메인 규칙(프롬프트·평가 기준)을 먼저 검증하고, 검증된 자산을 MCP·챗봇에
재사용하는 순서입니다.

## 사용법 (1단계 — 스킬)

Claude Code 세션에서 **"사고 확장"** 이라고 요청하면 `.claude/skills/six-hats/`
스킬이 실행됩니다. 파랑의 확인 질문부터 시작해 라운드마다 사용자 확인을 받으며 진행합니다.

| 파일 | 내용 |
|---|---|
| `SKILL.md` | 진행 절차 · 출력 형식 · 도구 사용 · 실패 처리 |
| `hats.md` | 모자 6개의 모드 · 씨앗 · 담당 축 |
| `scoring.md` | 채점 기준 · 탈락/병합 규칙 · 풀 관리 |
| `report.md` | 최종 보고서 형식 |

## 기술 스택 (2·3단계)

Python + **LangGraph** (여러 LLM 호출을 그래프로 엮어 순서·상태를 관리하는 프레임워크),
패키지 관리는 uv, 기본 모델은 `gpt-5.4-mini`.
아직 착수 전이라 빌드·실행 명령은 없습니다.
